# Security Review: FlowGrid

**Date:** 2026-03-17
**Reviewer:** Claude (automated)
**Scope:** Full codebase
**Overall Rating:** LOW RISK

---

## Executive Summary

FlowGrid is a client-side-only PWA puzzle game with no backend, no authentication, no user accounts, and no sensitive data processing. The attack surface is minimal. No critical or high severity issues were found. A handful of low/informational findings are documented below.

---

## Findings

### 1. [LOW] Vercel Project ID Committed to Repository

**File:** `.vercel/project.json`
**Description:** The `.vercel/project.json` file contains the Vercel `projectId` and `orgId`. While these are not secrets (they cannot be used to deploy or modify the project without authentication), they leak organizational metadata. The `.gitignore` already lists `.vercel`, so this should not be tracked — but the file exists on disk in the `.vercel/` directory.
**Status:** Mitigated — `.gitignore` already excludes `.vercel`. Verify it is not tracked in git.
**Recommendation:** Confirm `.vercel/` is not committed: `git ls-files .vercel`. If tracked, remove with `git rm --cached -r .vercel`.

---

### 2. [LOW] Generated Service Worker Committed to Public

**Files:** `public/sw.js`, `public/workbox-f1770938.js`
**Description:** The generated service worker files exist in `public/`. The `.gitignore` has patterns for `public/sw.js`, `public/sw.js.map`, `public/workbox-*.js`, and `public/workbox-*.js.map`, which should prevent them from being tracked. These are build artifacts and should not be in version control.
**Status:** Likely mitigated by `.gitignore`. Verify they are not tracked.
**Recommendation:** Confirm: `git ls-files public/sw.js public/workbox-*`.

---

### 3. [LOW] localStorage Data Not Validated on Read

**File:** `components/FlowGrid.jsx` (lines 33-41)
**Description:** The `loadStats()` function reads from `localStorage` and parses JSON. While wrapped in a `try/catch` (returning `null` on error), the parsed object is used directly without schema validation. A malicious or corrupted localStorage entry could inject unexpected property types (e.g., `gamesPlayed` as a string instead of number), potentially causing NaN displays or unexpected behavior in the UI. This is low risk because:
- localStorage is same-origin only
- The data is only used for display (stats, XP)
- No security-sensitive decisions depend on this data
**Recommendation:** Optionally add lightweight validation or default-merging when loading stats to ensure type safety.

---

### 4. [INFORMATIONAL] No Content Security Policy (CSP) Headers

**Description:** The application does not configure Content Security Policy headers. For a static client-side game with no inline scripts (Next.js handles this), no external API calls, and no user-generated content, the risk is minimal. However, CSP is a defense-in-depth measure.
**Recommendation:** Consider adding CSP headers via `next.config.mjs` security headers or Vercel configuration, particularly `default-src 'self'` and `script-src 'self'`. This would harden against any future XSS vectors.

---

### 5. [INFORMATIONAL] No Rate Limiting on Share Functionality

**File:** `components/FlowGrid.jsx` (lines 436-463)
**Description:** The `handleShare` function calls `navigator.share()` or `navigator.clipboard.writeText()` without throttling. This is purely cosmetic — a user could spam the share button, but the only effect is repeated clipboard writes or share dialogs. No server resources are consumed.
**Recommendation:** None required. The browser's own share dialog provides natural rate limiting.

---

### 6. [INFORMATIONAL] Daily Puzzle Seed is Predictable

**File:** `data/puzzles.js` (lines 839-846)
**Description:** The daily puzzle selection uses `YYYYMMDD % pool.length`, which is deterministic and predictable. Anyone can calculate which puzzle will appear on any future date. This is by design for a daily puzzle game (all players should get the same puzzle), but it means puzzle solutions could be pre-computed.
**Recommendation:** None — this is expected behavior for a daily puzzle mechanic. The puzzle pool is small (20 per size) so this is inherent.

---

### 7. [INFORMATIONAL] Puzzle Pool Cycles Every 20 Days

**File:** `data/puzzles.js`
**Description:** With only 20 puzzles per grid size, daily puzzles repeat roughly every 20 days. This is a gameplay concern rather than security, but regular players may recognize repeated puzzles.
**Recommendation:** Generate more puzzles to extend the cycle. Not a security concern.

## Conclusion

FlowGrid has a very small attack surface. It is a static, client-side-only puzzle game with no backend, no authentication, no user input beyond touch/pointer events, and no sensitive data. The codebase follows secure patterns: React JSX for rendering (preventing XSS), bounds-checking on grid coordinates, guarded localStorage access, and minimal dependencies. No action is urgently required. The low-severity items are minor hardening suggestions.
